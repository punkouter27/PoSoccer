# AGENTS.md — PoSoccer

Read this file first. It has three sections: **1. Coding standard** (the Po Game Standard this repo
follows, then the notes specific to PoSoccer), **2. Concurrent work** and **3. Verify the repo** (exact
commands). Long-form project notes (architecture, landmines, commands) are in
`docs/project-notes.md`; recorded rule exemptions in `docs/rules-exemptions.md`.

## 1. Coding standard

### Po Game Standard

This repo is one of several independent Po games. It follows the conventions below, but it owns every file:
nothing is generated from, synced with, or required to stay identical to another repository (no "same file in
every game" headers, no sync scripts that copy into other repos). Third-party code it needs (ML-Agents, MuJoCo
plugins, URLab) is vendored INSIDE this repo at a pinned version. Azure resources may be shared through `PoShared`.

#### Repo skeleton
```
README.md   AGENTS.md (this standard + repo notes)   CLAUDE.md ("Read AGENTS.md.")
docs/       lowercase, all prose (no DOCS/, no root DESIGN.md/SPEC.md/tasks.md — move them into docs/)
scripts/    build/publish/helper scripts (Unity: Tools/ is renamed scripts/ unless Unity itself needs it)
.github/workflows/<one file>.yml   the ONLY workflow
pyproject.toml with a [tool.ruff] section for any Python in the repo
```
No absolute local paths (C:\Users\...) committed anywhere. No build outputs or node_modules tracked.

#### Web page around the game (WebGL template / web viewer)
- The page chrome is drawn ONCE, by the HTML page, OUTSIDE the game canvas, so it can never overlap the HUD:
  a 44px top bar (game name top-left, settings gear / fullscreen top-right) and the version `vYYMMDD` bottom-right
  in the bar's counterpart or a 20px footer strip. The canvas fills the remaining viewport.
- The in-game HUD does NOT repeat the game name or version (it may show them inside menus, not as corner chrome).
- Same tokens as the web apps: dark background `#0b0f17`, surface `#121826`, text `#e6e9f2`, muted `#9aa3b5`,
  accent `#6366f1`, Inter/system-ui font. Text ≥ 4.5:1 contrast.

#### Orientation (C11)
The canvas fills any viewport (no fixed portrait aspect, no pillarboxing). UI is anchored and DPI-scaled
(Unity: CanvasScaler "Scale With Screen Size" or UI Toolkit PanelSettings scale-with-screen; Unreal: UMG anchors +
DPI curve). Must be checked at 1600x900 (landscape) and 450x800 (portrait) — screenshots in the PR/commit notes.

#### Version
One stamp, UTC `yyMMdd`, computed once by the publish/build script and injected into: index.html, diag.html,
and the player (`PlayerSettings.bundleVersion` / Unreal ProjectVersion) so `Application.version` matches the page.

#### /diag (games)
`/diag` (static `diag.html` generated by the publish script) titled **System status**, same layout as the web apps:
overall banner, then **API / Data / Services** sections. It must LIVE-probe (fetch from the browser, with latency)
every external dependency the game really calls (leaderboard tables/functions, weather APIs, AI APIs, replay bundles,
model files), plus the WebGL2 capability and that the build bundle files exist. Nothing hard-coded as "Ready".
The checks are listed in the repo's own config (e.g. `scripts/webgl.json` → `diagChecks`).

#### In-game diagnostics overlay (C12)
`Tab` (and a 44px corner button on touch devices) toggles an overlay showing: FPS, current episode reward,
inference latency (ms, rolling average), curriculum stage. Readable text (≥ 4.5:1 on an opaque panel).

#### Demo mode (C13)
After 30 s with no input (keyboard, mouse, touch, gamepad) from load or from last input: hide non-essential HUD,
all agents are driven by the trained policy (inference only), showcase cameras cycle (~6–8 s each); any input
returns control and the HUD. Idle threshold, camera list and dwell time are editor-tunable assets.

#### Rewards + editor-first config (C9, C10)
Reward includes penalties for joint torque², joint angular velocity², action rate ‖a_t − a_{t−1}‖², and foot sliding
(foot planar speed while in contact), each with its own weight. Reward weights, curriculum thresholds, cameras and UI
references live in ScriptableObjects / `[SerializeField]` (Unity) or DataAssets / `UPROPERTY(EditAnywhere,
BlueprintReadWrite)` (Unreal); Python trainers read the same values from the repo's training config. Changing a
penalty does not retrain shipped policies — note this in docs when shipped models predate the change.

#### Workflow
- Unity: the WebGL player is built locally with the EXACT pinned editor (Unity cannot be licensed in CI) by
  `scripts/publish_webgl.ps1`, which runs EditMode tests first, then builds, zips and publishes a `webgl-*` release.
  The one workflow: on release → deploy to the game's Static Web App → check the live page AND /diag; on push →
  Python checks (`ruff check`, `ruff format --check`, `pytest`) only.
- Unreal: the one workflow builds and deploys the repo's web front (viewer / showcase + /diag) to its Static Web App,
  after Python checks. The Unreal project must compile from a fresh clone (all plugins vendored in `Plugins/`).

#### Tests
Python: real pytest tests (collected by pytest, not ad-hoc scripts), ruff clean. Unity: EditMode tests pass before
every publish. Tests never write into tracked files.

  `Assets/Plugins`, `Assets/WebGLTemplates/Po` (Unity looks there), `Assets/ML-Agents` (git-ignored, written by
  the package) and `Packages/com.unity.ml-agents` (ML-Agents 4.1.0, locally patched, this repo's own copy).
  `Agent_EditMode_Naming` pins the layout. Move assets only with `git mv` of the asset **and** its `.meta`.
  Also: `scripts/` (build, publish, training and helper scripts), `docs/` (all prose), `tests/` (pytest), one
  workflow `.github/workflows/webgl.yml`.
- **Publish:** `pwsh -File scripts/publish_webgl.ps1` (close the editor; HEAD pushed first). It computes the
  UTC `yyMMdd` stamp once, runs the EditMode tests, builds with the exact pinned editor (the stamp reaches
  `PlayerSettings.bundleVersion` through `PO_BUILD_VERSION`, read by `Assets/_Project/Core/Editor/Editor_BuildStamp.cs`),
  checks `index.html` carries `vYYMMDD`, writes `diag.html` from `scripts/webgl.json` → `diagChecks`, zips
  and publishes a `webgl-*` release. The release runs the deploy job, which stamps the release's commit into
  every response as `X-Commit` and checks the live `X-Commit`, `/` and `/diag`. `-SkipBuild`, `-SkipTests`,
  `-NoPublish` exist; releases are never deleted unless `-Keep N` is passed. `scripts/deploy_webgl.ps1` deploys `Builds/WebGL`
  directly from this PC (az + SWA CLI) without GitHub.
- **Push:** every push to master (and every release, before it deploys) runs `ruff format --check`,
  `ruff check` and `pytest` (config in `pyproject.toml`). A push does not deploy; a `webgl-*` release does.
  Unity cannot be licensed in CI, so the Unity tests and the WebGL build run locally (section 3).
- **/diag** live-probes Open-Meteo (`Agent_Weather`, the only external call the game makes), every file
  of the build bundle, WebGL2, the game page and the deployed commit (`X-Commit`, "Missing" off Azure). `tests/test_webgl_config.py` fails if the C# gains an `https://` host
  that `diagChecks` does not probe. One probe round is kept 60 s per tab (sessionStorage, written by
  `scripts/publish_webgl.ps1`); `/diag?fresh` (the "Re-check now" link) probes again.
- **Page:** `Assets/WebGLTemplates/Po/index.html` draws the 44px top bar (name, fullscreen, /diag gear)
  and the 20px footer with `vYYMMDD`; the canvas fills the rest at any aspect, inside the page's `<main>`
  (the name is the page's `<h1>`; pinch zoom is not blocked, so axe's meta-viewport/region rules pass). The UI Toolkit panel
  (`Assets/_Project/UI/PanelSettings.asset`) scales with screen size in **Expand** mode against 1080x1920, so a
  portrait phone and a 16:9 desktop both get the full layout. The in-game chrome (`Agent_Chrome`) keeps
  the screen name, MENU, SETTINGS and a STATS corner button; product name and version are not on the canvas.
- **Tab overlay:** `Tab` / F3 / the STATS corner button (44px+, every device) opens `Agent_Telemetry`, an
  opaque panel whose first block is FPS, episode reward (focus or first Blue agent), inference latency
  (`Agent_InferenceClock`: rolling mean of the time between the last observation collected and the first
  action received in a decision step, i.e. the policy forward pass) and curriculum stage (goal width, bot
  strength, episode-steps lesson the trainer drives; their defaults at runtime), then **BENCHMARK TRAINING
  SPEED** (`Agent_SimBenchmark`: a few real seconds of the live pitch at full speed, reported as physics
  ticks/s, ML-Agents env steps/s and agent decisions/s, labelled with the CPU (logical cores) and GPU it ran on
  and what was measured; local simulation speed, not a training run; seconds and time scale in
  `DemoModeSettings.asset`).
- **Inference log:** the first decision of every ONNX brain prints one console line
  `[PoSoccer] <BRAIN>.onnx inference running (...)` (`Agent_InferenceLog`, called from
  `Agent_Soccer.OnActionReceived`). Check it in the browser console of the local WebGL build
  (`-NoPublish`) at 16:9 and 9:16.
- **Demo mode:** `Agent_DemoMode` + `Assets/_Project/Data/Resources/DemoModeSettings.asset` (idle seconds, camera shot
  list, dwell seconds). After 30 s with no keyboard / mouse / touch / gamepad input: in a watch match the
  HUD controls and chrome hide and the camera cycles; from the menu (or a 1-player match) an all-AI
  exhibition starts with every slot on its trained policy. Any input leaves demo mode (a demo started from
  the menu returns to it). The idle clock and the camera-dwell clock skip any frame longer than 0.25 s
  (`Agent_DemoMode.AdvanceClock`; WebGL warm-up, stalls, background tabs), pinned by EditMode
  `DemoMode_ALongLoadingFrameIsNotIdleTime` / `DemoMode_CameraDwellSkipsALongFrame`. Off in batch mode, headless runs and training.
- **Rewards:** agents are rigid `Rigidbody2D` discs (no joints, `docs/rules-exemptions.md` §2), so each
  penalty of the standard is charged on the disc, as its own reward-accounting term with its own weight on
  `Reward_Settings` (trainer override in brackets): action jitter L1 (`actionJitterScale`, `action_rate`),
  action rate ‖a_t − a_(t−1)‖² (`actionRateSquaredScale`, `action_rate_sq`), energy (traction-saturation² +
  turn², `energyPenaltyScale`, `energy_penalty`), torque² of the turn actuator (`torqueSquaredScale`,
  `torque_sq`), angular velocity² against the turn cap (`spinSquaredScale`, `spin_sq`) and foot sliding, the
  feet's sideways skid speed² (`footSlideScale`, `foot_slide`). `Agent_Soccer.ChargeControlPenalties` charges
  them; `Agent_PlayMode_ControlPenalties` proves each is charged on a live pitch. Profile defaults are 0 so
  every shipped `Reward_*.asset` keeps its trained reward; the active trainer configs in `Training/` set the
  weights. **The shipped `.onnx` brains predate these terms; nothing was retrained.** No motion-capture data
  exists in the repo, so there is no BC/AMP pre-training stage (PPO/POCA only).

**PoSoccer override:** this project trains with Unity ML-Agents (`mlagents`) on a top-down
2D Physics2D pitch. Every MuJoCo / `org.mujoco` / URLab / Newton / Isaac Lab / Blender-rig
line below does not apply; the realism rules apply through the exemptions recorded in
`docs/rules-exemptions.md`.

#### Agent rules (UU_AGENT)

Scope: RL-trained humanoids and animals with realistic motion on Earth, in Unity or Unreal.

##### 1. Workflow & Setup
- **Git:** Work on `master`. Commit before syncing or pulling. Check `docs/` first.
- **Automation:** Set up scenes, prefabs and levels via CLI and headless Blender. UI changes get before/after
  screenshots and an HTML report in `SCREENSHOTS/`.
- **Build stamp:** The build date `vYYMMDD` is shown bottom-right by the web page around the canvas (Po Game Standard: chrome outside the canvas); the in-game HUD does not repeat it.

| | Unity | Unreal Engine 5 |
|---|---|---|
| Background | Enable Run In Background | Disable Use Less CPU when in Background |
| Raw assets | `Assets/_Project/Environments/Art/Raw/` | `Content/Art/Raw/` |
| Exported assets | `Assets/_Project/Environments/Art/Exports/GLB/` | `Content/Art/Exports/` |
| Physics | MuJoCo (`org.mujoco`), not PhysX | MuJoCo / URLab, not Chaos |
| Policy runtime | Unity Sentis / ONNX | NNE / ONNX Runtime |

##### 2. Physics & Realism
- **Collision:** Primitive colliders only (capsules, spheres, boxes). Non-adjacent parts collide with each other.
  Zero penetration at rest, at joint limits and through motion.
- **Fidelity:** Gravity −9.81 m/s², anatomical mass, realistic joint, torque and speed limits. Skeleton joints
  match between the 3D files and the simulator.
- **Smooth motion:** Rewards carry action-rate/jerk penalties (or low-pass filtering): fluid motion, no jitter.

##### 3. Policy Architecture & Retraining
- **Hierarchy:** A few small policies, one per motor skill family (locomotion, balance/get-up, task skills). Cover
  variants with command inputs (velocity, gait, target, style), not new policies. Layered rule-based directors
  (game flow → body → skill) switch policies on physical state (contacts, centre of mass, falls) through one
  transition table, mirrored in every runtime. Policies never pick each other.
- **Hand-overs:** All policies of a body share the observation layout, joint order, action map, timing and
  motion-style reward. Preload every policy. Pass on the last action; never snap poses or blend outputs. Train each
  policy on the states it inherits (get-up from real falls).
- **Frozen interface:** Append inputs only at the end, with zero-initialised weights; never reorder or remove them.
  If the interface must break, distil the old policy into the new layout.
- **One brain per character:** Every new character gets its own training run and its own policies. No character
  reuses another's brain, even when the bodies are similar. Personality comes from the character card's traits and
  its own style reward weights, learned in training. Directors don't script it. Each character trains from scratch,
  passes every ladder level and the gate, and trains against the existing roster. Once a character is trained, try
  to avoid retraining it fully.
- **Before any change:** List the policies it touches (body physics → that body's; rules → the policies acting
  under them; new skill → its policy plus director rows; visuals → none) and log that in `/DOCS`. Afterwards, re-run
  every policy's regression scenarios (task + realism). Tag each checkpoint with its interface and physics versions.

##### 4. Training, Gates & Reports
- **Execution:** Close the editor for runs over 30 min or when free RAM drops below 4 GB. Save and commit first.
- **Cleanup:** Delete failed runs, short tests (<5,000 steps) and unneeded checkpoints. Never delete a run written
  to in the last 24 h or one a queue will resume.
- **Graduation gate:** Export ONNX only after the target score holds for 100 straight episodes with no NaN gradients.
- **Telemetry:** Run TensorBoard with every run. Log metrics and progress to `docs/<YYYYMMDD>/` so later agents can
  pick up where a run left off.
- **Reports & updates:** Runs over 30 min get an HTML report with metric charts and run-over-run deltas. Estimate
  training time at startup. Send hourly updates (status grid, key improvements, short summary).

##### 5. Communication
- **Large changes:** Over 100 lines of code: offer 3 roadmap/architecture questions.
- **Summary:** Responses over 100 words end with a ~20-word TL;DR.
- **Problem solving:** End with a proposed fix for the app's main open issue and ask before acting on it.

#### CI/CD and Azure
- WebGL is built locally (see Publish above) and deployed by `.github/workflows/webgl.yml` on a

## 2. Concurrent work

- Only `master` exists, locally and on GitHub. Before every commit and push:
  `git fetch origin && git rebase --autostash origin/master` (only your own unpushed commits).
- Stage only your own files (`git add <paths>`, never `git add -A`); check `git diff --cached`. Unity
  re-saves `ProjectSettings/ProjectSettings.asset` (the WebGL scripting defines) on most runs: do not commit
  that churn by accident.
- Never edit `.unity` scenes or `.meta` files by hand, and never while the Editor has the project open.
- One Unity instance (Editor or batch mode) and one headless browser at a time; close them when done.
  Training runs over 30 min need the Editor closed (section 1, UU_AGENT 4).
- Ask the owner before renaming or deleting Azure resources, deleting releases or rewriting git history.

## 3. Verify the repo (exact commands, from the repo root)

One command sequence verifies the repo (close the Editor first; last full run 2026-11-23, three in a row: pytest 15 passed, EditMode
213/213, PlayMode 114 passed, 3 opt-in captures skipped, 0 warnings):

```powershell
$env:CI = 'true'; $env:UNITY_MCP_KEEP_CONNECTED = 'false'; $U = "C:\Program Files\Unity\Hub\Editor\6000.6.9f1\Editor\Unity.exe"
uvx ruff@0.17.6 format --check . && uvx ruff@0.17.6 check . && uvx --with pytest pytest -q && & $U -batchmode -nographics -projectPath . -runTests -testPlatform EditMode -assemblyNames PoSoccer.EditModeTests -testResults Logs/editmode.xml -logFile Logs/editmode.log && & $U -batchmode -force-d3d11 -projectPath . -runTests -testPlatform PlayMode -assemblyNames PoSoccer.PlayModeTests -testResults Logs/playmode.xml -logFile Logs/playmode.log
```
